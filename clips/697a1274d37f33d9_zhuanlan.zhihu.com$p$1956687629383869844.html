使用stun暴露飞牛影视到公网

之前用群晖的时候，使用emby作为影音服务器，为此还买了一个emby的primeier的账号。使用lucky+stun将emby服务器暴露到公网上，这样可以在任意地方使用浏览器访问emby，播放影音。具体做法可以参照构建可以公网访问的影音服务器。

但是这样做有一个缺陷，就是emby的客户端不怎么好用，因为每次映射的端口都是动态的，导致每次打开客户端都要在浏览器上获取emby服务器的端口，然后在客户端重新填写emby服务器的端口，有点麻烦。

最好的方法提供一个服务，然后动态的获取emby的端口，将请求转发到后端的的emby服务器，类似于下图

这样，cfworker需要提供两个接口

  1. /webhook: 供lucky注册emby服务器的ddns和端口
  2. /server: 用于 emby服务器的ddns和端口的发现

其他请求就从kv里获取emby服务器的后端地址和端口，然后转发过去就行了。这样就形成一个完整的服务了。下面的worker.js可以提交到cloudflare，创建一个worker，实现这样的功能：

export default {
    async fetch(request, env) {
        const url = new URL(request.url);

        if (url.pathname === "/webhook" && request.method === "GET") {
            return handleWebhook(url, env);
        }

        if (url.pathname === "/server" && request.method === "GET") {
            return handleServer(url, env);
        }
        
        return proxy(request, env);
    }
};
async function handleWebhook(url, env) {
  const uuid = url.searchParams.get("uuid");
  const app = url.searchParams.get("app");
  const addr = url.searchParams.get("addr");

  // 预设的 UUID，请在这里替换成你的真实 UUID，避免别人猜到你的地址
  const PRESET_UUID = "xxxxx";

  if (!uuid || !app || !addr) {
    return new Response("Missing parameters", { status: 400 });
  }

  if (uuid !== PRESET_UUID) {
    return new Response("Unauthorized", { status: 403 });
  }

  try {
    await env.APP_STORAGE.put(app, addr);
    return new Response("Success", { status: 200 });
  } catch (error) {
    return new Response("Error saving data", { status: 500 });
  }
}

async function handleServer(url, env) {
  const app = url.searchParams.get("app");

  if (!app) {
    return new Response("Missing 'app' parameter", { status: 400 });
  }

  try {
    const addr = await env.APP_STORAGE.get(app);
    if (!addr) {
      return new Response("App not found", { status: 404 });
    }

    return Response.redirect(addr, 302);
  } catch (error) {
    return new Response("Error retrieving data", { status: 500 });
  }
}

async function proxy(request, env) {
    const url = new URL(request.url);
    const APP = "fnos"
    // 从 KV 获取 host1，例如 1.2.3.4:8080
    const host1 = await env.APP_STORAGE.get(APP);
    if (!host1) {
        return new Response("Backend fnos not configured", {status: 500});
    }
    const newRequest = new Request(targetUrl, request);
    return fetch(newRequest);
}

在cloudflare上创建一个worker，设置自定义的域名（去买一个.xyz的数字域名，10年才需要几十块钱），把域名dns托管到cf上，完全免费，


同时，在dash.cloudflare.com里登录，选择存储与数据库--worker KV，创建一个kv，名称为APP_STORAGE，在worker上关联该kv。

即可实现完成该服务。


但是这样有一个缺陷，就是所有流量都要通过cloudflare，日常的管理没啥问题，但是要通过emby来观看影视，cloudflare的免费流量显然不够用，所以弄完这个之后，还需要进一步优化。但是一直没时间弄，就拖着。

后面我嫌群晖配置太差了，弄了个威联通qnap ts-464c，双2.5g网卡，4盘位，再后来，觉得qnap原生的系统太慢了，就又给装上了飞牛os，折腾了一个星期多把威联通装上了飞牛NAS。又开始琢磨怎么优化飞牛影音，抓了一下飞牛的数据包，发现他在播放电影时，访问的url如下

http://fnos.xxx.xyz/v/media/250ee32b86fbfb5369e22443bba6399c/00012.ts

我想，能不能在访问这个url的时候进行判断，做一个302跳转，直接返回实际的stun后的地址，http://home.xxx.xyz:31258/v/media/250ee32b86fbfb5369e22443bba6399c/00012.ts，而不是代理，这样不就可以不用走cf的流量吗，所以修改了一下worker.js proxy的代码 ，发现果然可以：

async function proxy(request, env) {
    const url = new URL(request.url);
    const APP = "fnos"
    // 从 KV 获取 host1，例如 1.2.3.4:8080
    const host1 = await env.APP_STORAGE.get(APP);
    if (!host1) {
        return new Response("Backend fnos not configured", {status: 500});
    }

    // 定义图片和视频文件后缀
    const mediaExtensions = [ ".ts", ".mp4", ".mkv"];
    const pathname = url.pathname.toLowerCase();

    // 判断是否为媒体文件请求
    let isMedia = mediaExtensions.some(ext => pathname.endsWith(ext));

    // 如果 Accept 头包含 image/*，也视为媒体请求
    // const acceptHeader = request.headers.get("Accept") || "";
    // if (acceptHeader.startsWith("image/")) {
    //     isMedia = true;
    // }
    const targetUrl = `http://${host1}${url.pathname}${url.search}`;

    if (isMedia) {
        // 302 跳转
        console.log("Redirect:", {path: url.pathname, target: targetUrl});
        return Response.redirect(targetUrl, 302);
    } else {
        // 转发到 host1
        console.log("Fetch:", {path: url.pathname, target: targetUrl});
        const newRequest = new Request(targetUrl, request);
        return fetch(newRequest);
    }
}

就是说如果客户端访问非图片和影音的数据，就使用代理模式，如果访问图片和影音的数据，就使用redirect模式，通过网页和飞牛客户端的测试，这种模式对影音适用，但是对图片还不适用，所以图片仍然通过cf代理。



调试过程中，我用到了 mitmproxy，可以抓所有的网络访问请求，这里可以看到

在访问.ts文件时，浏览器确实相应了302跳转，直接从stun后的端口直接访问影像文件了。这样就可以愉快的在公网使用 fnos.xxxx.xyz的服务器名来登录飞牛的nas，进行各种操作以及观看电影了。

目前还有一个缺陷就是图片文件不能响应302跳转，但是好在图片流量不算大，只是浏览的话，不会有任何问题。后续考虑怎么跳过代理访问图片。
