使用stun解决无公网ip的家庭网络外部访问的问题

前言

家里的网络架构是这样的

自从安装了联通FTTR千兆之后，就不提供IPV4的公网ip了。外网访问家里的nas就只能使用IPV6。而IPV6经常被QoS，访问很不顺畅，同时很多场合，尤其是使用wifi的地方，都不支持ipv6。很不爽。

STUN打洞原理

后来在网上看到可以利用stun来对内网进行打洞，帮助外部网络访问NAT后内部网络。打洞的原理如下：

STUN（Session Traversal Utilities for NAT）服务器 帮助 NAT 后的设备发现其公网 IP 和端口，从而 创建 NAT 映射，允许外网设备访问内网设备。

主要步骤：

  1. 内网主机 A 向 STUN 服务器发送 UDP 请求
  2. 目标地址：stun.server.com:3478
  3. NAT 设备会 动态分配一个外部端口（如 1.2.3.4:60000）
  4. STUN 服务器返回 A 的公网地址和端口
  5. A 发现自己的 NAT 分配地址为 1.2.3.4:60000
  6. A 发送给 B 这个地址信息
  7. 外网主机 B 直接向 1.2.3.4:60000 发送数据
  8. NAT 路由器 已经为 A 创建了端口映射，B 发送的流量 会被 NAT 转发到 A

通常没有公网IP的网络通过网关访问外网，都走的NAT网络，STUN 适用于 “对称 NAT” 以外的 NAT 类型：

  • ✅ Full Cone NAT（完全锥形 NAT） → 最容易打洞
  • ✅ Restricted Cone NAT（受限锥形 NAT） → 可以打洞
  • ✅ Port Restricted Cone NAT（端口受限锥形 NAT） → 通常可以打洞
  • ❌ Symmetric NAT（对称 NAT） → 几乎无法打洞，需要 TURN 服务器中继

如果 NAT 是对称 NAT（如企业防火墙、ISP 级 NAT），则 STUN 无法直接打洞，需要 TURN（Traversal Using Relays around NAT） 服务器中继流量。

如何确认自己所在的局域网是哪种NAT类型，可以使用python的stun包来确认，

>pip install pystun3
>python
>>>import stun
>>>stun.get_ip_info()
('Restric Port NAT', None, None)

这样表示你所在的局域网是始于NAT2，是可以实现打洞的。

Openwrt上如何实现STUN打洞

安装lucky

可以在openwrt上安装lucky软件，我下载的地址是https://github.com/gdy666/luci-app-lucky， 下载luci-app 和lucky对应的安装包在openwrt安装即可。

安装完后，可以开启lucky，并访问lucky的配置页面，通常是 http://:16661，设置认证方式和访问url。


光猫配置dmz

因为lucky运行在软路由之上，而光猫采用的是路由而非桥接的方式，所以需要在光猫上开启dmz模式，把软路由设为dmz取，方便外部stun打洞的端口通过光猫转发到路由器上。因为光猫也没有公网IP，所以这一步也是安全的。当然如果你配置能力很强，也可以通过NAT只允许特定的端口映射到软路由上。



如果你的路由器wan口选择的是dhcp，你也可以使用mac映射，避免wan口获得的ip改变。

ddns配置

因为家用网络的ip是经常发生变化的，那么在外面如何快速找到家里ip的信息呢，我们可以使用ddns，lucky也支持ddns，这里我们使用cloudflare的ddns功能，首先我去dnspod花8块钱买了个dns域名，然后把他托管到cloudflare上。然后就可以在cloudflare上自定义域名解析了。

lucky里就可以设置ddns了。设置ddns的过程大同小异，设置完成后，在lucky可以看到是否生效。


也可以在命令行通过 nslookup home.xxx.site检测是否生效。

进阶配置

通过stun和ddns，我们就可以通过 http://home.xxx.site:2128 来访问家里的emby服务器了，这里的2128就是在stun内网穿透里暴露出来的端口，在配置界面会显示。

但是这个2128会随时发生变化，我们如何固定使用某个url来访问emby服务器呢，不管ip和映射的端口如何发生变化。这时候，我们需要开启lucky stun的webhook功能和cf的page功能。

cf的page提供在线免费的api接口，这里我们设置两个接口，一个是/webhook用于lucky在stun映射的端口发生变化时通知新的端口；一个是/service，用于查询对应服务的端口。在cloudflare的dashboard里点击workers和pages点击创建新的pages，选择空白的hello world模板，然后点击部署，并修改源代码，将下列源代码复制过去：

export default {
  async fetch(request, env) {
    const url = new URL(request.url);

    if (url.pathname === "/webhook" && request.method === "GET") {
      return handleWebhook(url, env);
    }

    if (url.pathname === "/server" && request.method === "GET") {
      return handleServer(url, env);
    }

    return new Response("Not Found", { status: 404 });
  }
};

async function handleWebhook(url, env) {
  const uuid = url.searchParams.get("uuid");
  const app = url.searchParams.get("app");
  const addr = url.searchParams.get("addr");

  // 预设的 UUID，请在这里替换成你的真实 UUID，避免别人猜到你的地址
  const PRESET_UUID = "xxxxx";

  if (!uuid || !app || !addr) {
    return new Response("Missing parameters", { status: 400 });
  }

  if (uuid !== PRESET_UUID) {
    return new Response("Unauthorized", { status: 403 });
  }

  try {
    await env.APP_STORAGE.put(app, addr);
    return new Response("Success", { status: 200 });
  } catch (error) {
    return new Response("Error saving data", { status: 500 });
  }
}

async function handleServer(url, env) {
  const app = url.searchParams.get("app");

  if (!app) {
    return new Response("Missing 'app' parameter", { status: 400 });
  }

  try {
    const addr = await env.APP_STORAGE.get(app);
    if (!addr) {
      return new Response("App not found", { status: 404 });
    }

    return Response.redirect(addr, 302);
  } catch (error) {
    return new Response("Error retrieving data", { status: 500 });
  }
}

这里webhook上传的app和addr的映射，我们放在cloudflare为我们提供的免费kv服务里。我们在编辑完代码并部署后，需要在设置里修改下列参数：

  1. 自定义域名：可以在我们刚才添加的里添加子域名，比如app.xxx.site，这样我们可以通过https://app.xxx.site/webook|server 来访问对应的服务。在设置-->域和路由里添加自定义域,输入 app.xxx.site即可。
  2. 绑定kv：我们在cloudflare里存储和数据库--kv创建一个kv库，取名为APP_STORAGE，然后在pages的设置--绑定里添加 KV命令空间，名称为APP_STORAGE，值为APP_STORAGE 即可。

部署完成后，我们可以在本地使用curl命令测试服务是否成功，比如运行

>curl https://app.xxx.site/webhook?uuid=xxxx&app=emby&addr=http://home.xxx.site:2128

就可以在cloudflare里存储和数据库--kv--APP_STORAGE里看到对应的app/addr值。

同时，使用

>curl https://app.xxx.site/server?app=emby

可以显示跳转到http://home.xxx.site:2128。

这时候我们还要回到lucky去配置stun的webhook，以便于每次stun对应的端口发生变化，能及时同步到cloudflare上，这里回到lucky的配置界面，在stun内网穿透的配置里增加规则的webkook配置，如下：


这里的接口地址为https://app.xxx.site/webhook?uuid=<cloudflare上设置的uuid>&app=#{ruleName}&addr=http://home.xxx.site:#{port}

配置完成后，每次stun打洞的端口发生变化是，都可以同步到cloudflare上，而我们通过 http://app.xxx.site/server?app=emby，即可自动跳转到更新的ip和端口上，实现自动跳转。
